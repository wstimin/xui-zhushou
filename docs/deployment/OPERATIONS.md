# 更新、备份与常见问题

## 更新责任

一键脚本不使用网页安装向导：安装时在终端初始化，`pa status` 查看完整信息，`pa init` 仅补做未完成的初始化，`pa password` 重置超级管理员密码。账号密码最低 6 位；已有密码不能从哈希反查。

从 v2.2.1 或更早版本升级到 v2.2.2 时，先按 README 使用新版远端脚本的 `update` 子命令迁移旧进程名，不使用旧脚本或旧后台执行器做此次迁移；新进程名为 `panelark`，旧安装目录保持不变以保护数据。

- 一键脚本独立安装：输入 `pa` 打开管理菜单，`pa check-update` 或菜单 [11] 只检测版本；`pa update` 或菜单 [15] 才执行更新，交互终端还需确认；相同版本不下载、不重复安装。`pa start/stop/restart/logs/status` 分别管理本项目服务。旧命令 `sy` 保留兼容；满足 systemd/PM2 条件时也可用后台签名在线更新。
- 宝塔 / 1Panel Node 项目：在面板停止项目，备份数据，替换程序包、安装变更的依赖，由面板启动。
- Docker / 1Panel 编排：保留卷名和编排项目名，备份后重新构建、启动容器。
- 不要把面板项目交给本项目的独立 PM2/systemd 更新器，它不知道面板的路径、运行用户、容器网络和进程管理方式。启动 `panel.cjs` 会自动设置部署模式并在后台提示正确更新方式。

后台更新分为“检测更新 → 下载并安装更新”两步。检测不会下载构建包、备份或重启；点击安装并在站内弹窗确认后，系统使用本机托管密钥自动创建更新前备份，并连续完成下载、签名校验、应用、重启和健康检查，不再要求输入备份密码。手动迁移备份仍使用用户密码，最低 6 位并建议使用更长的随机密码。宝塔 / 1Panel / Docker 部署仍由外部面板或容器管理程序升级，后台只显示适用的操作。

后台明暗主题与前台共用暖象牙 / 暖黑深棕＋金色设计，主题偏好保存在浏览器；所有提示使用居中的站内主题弹窗。后台列表按服务端分页查询，默认每页 20 条，可切换 10/20/50/100 条并访问历史记录。

CDK 的查看、复制、TXT / CSV 导出、编辑、删除与批量操作见 [CDK 管理说明](CDK.md)。新生成 CDK 可以重新读取；旧版哈希不能逆向恢复，但可以绑定你已保存的原始授权码。管理员密码仍为不可逆哈希，与可恢复的 CDK 加密副本不同。

## 必须保留的数据

`PANELARK_DATA_DIR` 下的全部内容，包括 `panelark.sqlite`、`panelark.secret`、备份目录、更新与审计数据。SQLite 和 secret 必须一起迁移，否则既有 CDK 将无法验证。项目 `.env`、面板环境变量、域名、代理和证书配置也需单独备份。

后台“备份”可以生成 `.pgbak` 加密备份；备份密码不保存到数据库，请自己保管。更换服务器恢复后重新登录并检查套餐、CDK、后台路径。面板自身备份网站时，也要确认它覆盖独立数据目录或 Docker 卷。

## 常见问题

| 现象 | 排查方式 |
| --- | --- |
| 绑定域名后 502 | 检查 Node/容器是否运行、Node 是否为 24+、启动目录是否正确、代理端口是否与 PORT 一致；不要选择 PHP/静态运行环境 |
| 源码首次启动长时间无页面 | 查看首次 `npm ci` 和构建日志；检查 npm 网络、可用内存/磁盘；资源较小可改用预编译面板 ZIP |
| 1Panel 代理连接被拒绝 | OpenResty 容器的 127.0.0.1 是它自己；使用实际可达的宿主机网关，或按本文档配置同一网络的 panelark-app:1888 |
| 数据目录权限错误 | 检查面板实际运行 UID/GID 和挂载目录所有者，只授予该用户所需权限，不要使用 777 |
| 安装令牌无效 | 确认访问的实例/数据目录与读取的令牌一致；预设 PANELARK_SETUP_TOKEN 时以该值为准；不要把 CDK 当作安装令牌 |
| 已安装，仍看到旧向导 | 刷新页面；检查是否连到另一容器、错误数据卷或重建后更换了数据目录 |
| /install 显示已安装 | 这是正常锁定；通过自己保存的后台路径登录，无需删除数据重新安装 |
| HTTPS 下登录后掉线 | 检查代理传递 X-Forwarded-Proto: https、后端信任的是正确代理、是否代理了整个 /api；不要在 HTTP 和 HTTPS 两个入口间混用会话 |
| 安装任务日志迟迟不刷新 | 关闭反向代理缓冲/缓存，设置读取超时；SSE 是普通长连接 HTTP，不应由静态站点缓存处理 |
| 上传备份报 413 | 代理设置 client_max_body_size 30m；应用加密备份上限 25 MB |
| 修改源码后仍是旧界面 | 重新构建 dist；panel.cjs 只在 dist 缺失时自动构建，不会在每次重启时编译 |
| 更新后依赖错误 | 停止项目，在正确 Node 24 环境执行 npm ci --omit=dev --ignore-scripts；纯源码构建先安装开发依赖再 build |
| 项目不能在目标 VPS 安装 | 检查项目卡片系统/资源要求、SSH 权限、官方软件源/容器仓库连通性以及端口冲突；平台部署成功不代表所有目标面板可装在任意系统 |

## 健康检查与验证

`GET /api/health` 应返回 HTTP 200、`status: ok` 和当前版本。一键脚本：首页正常打开、`/install` 返回 404，管理员由终端创建后可登录。宝塔/1Panel/容器：首次首页跳转 `/install`，环境检查全部通过；初始化后刷新向导显示已安装。公网首页应能读取项目目录。首次上线请测试一个授权任务的完整流程。

使用 HTTPS 后再输入管理员和 SSH 信息。面板 TLS 终止与目标 VPS 面板 TLS 是两套配置；网页安装向导不会替你修改 DNS、签发目标面板证书或修改云厂商安全组。
