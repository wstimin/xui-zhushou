## 1. 产品定义

PanelArk 是一个带 CDK 商业授权的 VPS 可视化部署与交付平台。用户输入服务器 SSH 信息后，系统自动完成环境检测、依赖补齐、端口与防火墙处理、面板安装、运行验证和结果交付；代理类面板还可继续创建节点、订阅和二维码。

品牌信息：

- 中文名：面板方舟
- 英文名：PanelArk
- 产品名：PanelArk VPS 一键部署助手
- 宣传语：连接服务器，一键装好所需面板
- CDK 前缀：`PAK-`
- 全站备份扩展名：`.pgbak`

## 2. 产品边界

### 2.1 PanelArk 负责

- CDK 验证、锁定、核销、返还和套餐控制。
- CDK 购买链接和客服入口展示。
- SSH 密码或私钥连接及主机指纹确认。
- Linux 系统、架构、权限、资源、网络和端口检测。
- 自动安装安全且缺失的基础依赖。
- 面板兼容性判断和动态配置表单。
- 自动安装面板、工具和必要运行环境。
- 本机防火墙放行、端口冲突识别和交互式处理。
- 云厂商安全组未放行时给出准确提示并支持重新检测。
- 可恢复的部署任务、结构化进度和脱敏日志。
- 服务、端口、网页、凭据和 API 的安装后验证。
- 面板登录信息和客户交付信息整理。
- 代理面板的节点、订阅、二维码和 SOCKS 路由能力。
- 管理后台、管理员权限、资源推荐、在线更新和全站备份迁移。

### 2.2 PanelArk 不负责

- 长期监控客户服务器的 CPU、内存或流量。
- 作为客户服务器的文件管理器或日常 WebSSH 运维后台。
- 长期接管客户网站、数据库、Docker 或邮件业务。
- 替代被安装的 1Panel、宝塔、3x-ui 等面板。
- 向普通用户开放任意 Shell 命令或任意安装脚本 URL。

PanelArk 可以帮用户安装哪吒、Uptime Kuma 等监控面板，但 PanelArk 自身不发展成监控平台。

## 3. 用户端主流程

```text
访问首页并浏览面板
→ 点击开始部署
→ CDK 操作权限验证
→ 解锁服务器与部署表单
→ 输入服务器信息
→ SSH 连接与主机指纹确认
→ 环境检测
→ 自动安装安全依赖
→ 选择兼容面板
→ 确认配置与执行计划
→ 处理端口、防火墙及服务冲突
→ 锁定 CDK 权益
→ 自动安装
→ 验证面板
→ 成功后核销 CDK
→ 返回交付信息
→ 代理面板可继续搭建节点
```

## 4. CDK 与购买入口

### 4.1 CDK 类型

- 单次安装码。
- 多次安装码。
- 指定面板码。
- 指定分类码。
- 代理面板加节点套餐码。
- 全面板套餐码。
- 带有效期的 CDK。
- 时间会员码作为后续能力。

### 4.2 CDK 状态

```text
未使用 → 已验证 → 已锁定 → 已核销
```

异常状态包括：已过期、已禁用、已退款、待人工审核。

### 4.3 核销规则

- 验证 CDK 不扣次数。
- SSH 连接失败、系统不兼容或用户未开始安装不扣次数。
- 用户确认安装后临时锁定权益。
- 面板安装且验证成功后正式核销。
- 平台错误自动释放权益。
- 用户在执行阶段取消或产生不确定残留时进入人工审核。
- 同一任务重试必须幂等，不能重复核销。

### 4.4 部署门禁与购买入口

CDK 不是网站浏览门禁，但它是所有部署操作的权限门禁。未验证 CDK 的访客可以访问首页、查看面板目录、工具箱、文档、关于和资源推荐，但不能填写服务器信息、打开部署配置或提交任何执行型表单。

用户点击“开始部署”“连接服务器”或任一安装按钮时，系统先弹出 CDK 验证。验证成功后解锁本次会话的服务器信息填写和部署流程；此时只验证权益，不立即扣除次数。真正点击确认安装时再锁定权益，面板安装并验证成功后正式核销。

部署顺序必须固定为：验证 CDK、填写并检测服务器、选择兼容面板、配置并安装。公开面板目录允许提前浏览，但检测服务器之前的面板点击不得预选、暂存或自动延续该面板；服务器检测完成后只展示兼容面板目录，由用户重新主动选择。

首页开始区域必须将“购买 CDK”与“验证 CDK”作为相邻操作展示；CDK 验证弹窗中同样同时保留验证和购买按钮，避免用户输入授权码失败后无处购买。

部署授权弹窗及额度不足提示中必须提供“购买 CDK”按钮。后台可配置：

- 是否显示。
- 按钮文案。
- 全局购买链接。
- 不同套餐对应的购买链接。
- 客服和售后链接。
- 公告内容。
- 页面展示位置。

只允许配置安全的 HTTPS 链接，不允许注入脚本或任意 HTML。

## 5. 服务器连接与检测

用户填写：服务器地址、SSH 端口、SSH 用户名、密码或私钥、可选私钥密码。

服务器表单采用“仅当前页面临时保留”策略：输入内容只存在前端运行内存，不写入数据库、`localStorage`、`sessionStorage` 或其他永久存储。误关弹窗后在同一页面重新打开可恢复草稿；刷新页面、关闭标签页或重新进入站点后全部清空。界面必须在表单上方明确提醒该规则。

服务器表单不得通过点击遮罩层关闭。用户已填写内容后点击关闭或取消，应显示退出确认并说明当前页面内仍会保留、刷新后会丢失；检测过程中禁止直接关闭。SSH 密码与私钥同样只允许在当前页面内存中短暂存在。

自动检测：

- 操作系统、版本和 CPU 架构。
- CPU、内存、磁盘和交换空间。
- root 或免密 sudo 权限。
- systemd 或 OpenRC。
- apt、dnf、yum、apk、pacman、zypper 等包管理器。
- Docker、Docker Compose 和常用系统命令。
- IPv4、IPv6、DNS 和外部下载能力。
- 端口占用、防火墙和已有服务。
- 可能已经安装的面板。
- SSH 主机指纹。

检测状态分为：完全兼容、兼容但有警告、缺少依赖可自动处理、存在冲突需要选择、不兼容。

## 6. 自动依赖系统

每个面板适配器声明支持系统、架构、最低内存和磁盘、依赖软件包、服务、Docker、数据库和端口要求。

可自动安装的基础依赖包括：

- curl、wget、tar、gzip、unzip、jq。
- openssl、ca-certificates、Git、socat、cron、lsof、iproute2。
- Docker Engine、Docker Compose。
- 面板必需且经过审核的软件源。

安装依赖后必须再次验证命令、版本和服务状态。

替换数据库、修改 SSH 端口、更换内核、关闭 SELinux、覆盖目录、卸载已有服务或清空防火墙等高风险操作必须暂停并由用户确认。

## 7. 端口、防火墙与冲突处理

### 7.1 本机防火墙

自动识别 UFW、firewalld、iptables 和 nftables。

- 面板长期端口添加永久规则。
- 证书验证临时端口在任务结束后恢复。
- 已存在的规则不能重复添加或错误删除。

### 7.2 云厂商安全组

当服务已经监听、本机防火墙也已放行但公网仍不可达时，提示用户前往 VPS 厂商后台放行，并显示协议、端口、建议来源和操作说明。

用户可以选择重新检测、复制端口、查看教程或稍后处理。证书验证等强依赖端口不能直接忽略。

### 7.3 端口被占用

系统显示占用端口的进程、PID、systemd 服务、Docker 容器和监听地址，并允许：

1. 自动更换可用端口。
2. 临时停止占用服务。
3. 用户自行处理后重新检测。
4. 取消安装。

临时停止服务前记录原始状态。无论安装成功、失败、取消、断线或超时，都必须恢复原服务并验证恢复结果。

## 8. 面板与工具目录

### 8.1 面板分类

- 服务器面板。
- 建站面板。
- 代理面板。
- Docker 面板。
- 监控面板。
- NAS 与文件面板。
- 游戏面板。
- 邮件面板。
- 订阅与销售面板。
- 其他工具。

### 8.2 首批目标

代理类：3x-ui、S-UI、Marzban、Hiddify Manager。

建站类：1Panel、aaPanel、宝塔 Linux 面板。通用类：CasaOS、Portainer、Nginx Proxy Manager、哪吒监控、Uptime Kuma。AI 类：New API、One API、CLIProxyAPI。

后续逐步覆盖 Webmin、Cockpit、CloudPanel、CyberPanel、HestiaCP、Dockge、Cloudreve、AList/OpenList、Vaultwarden、MCSManager、Pterodactyl、Mailcow、File Browser、XBoard/V2Board 相关组件等。

只有经过适配和验证的项目才能上架，不能以“任意脚本执行”冒充全面支持。

### 8.3 工具箱

第一批工具包括 Docker、Docker Compose、Nginx、Fail2Ban、BBR、Swap、Git、Certbot/acme.sh 和常用系统依赖。工具箱只负责一次性安装或配置，不承担长期运维。

## 9. 面板适配器

每个面板以独立适配器接入，包含：

- 元数据与分类。
- 兼容性和资源要求。
- 动态配置表单。
- 能力声明。
- 安装前检查。
- 部署计划。
- 安装步骤与进度事件。
- 健康检查与结果提取。
- 失败恢复和临时环境清理。

优先使用官方非交互参数、官方安装器、官方镜像、审核后的 Compose 模板、固定版本和校验和，不依赖易变的交互菜单编号。

## 10. 部署任务与结果

任务状态包括：等待检测、检测中、等待确认、准备依赖、安装依赖、处理端口、安装面板、启动服务、验证面板、恢复环境、成功、失败、需要人工处理和已取消。

任务必须后端持久化，支持页面刷新、浏览器断线和后台重启后恢复。同一服务器不能同时执行多个高风险任务。

成功结果包括：面板名称和版本、访问地址、管理员账号密码、端口、入口路径、API Token、SSL 状态、服务状态、数据目录、云安全组端口、安装时间和注意事项。

支持单项复制、一键复制、敏感信息显隐、TXT 交付单、后续 PDF、标记已交付和删除敏感结果。

## 11. 代理节点能力

代理面板安装成功后提供独立的“继续搭建节点”任务，避免节点失败被误认为面板安装失败。

目标模板包括：

- VLESS + TCP + Reality。
- VLESS + WebSocket + TLS。
- VLESS + gRPC + TLS。
- VMess、Trojan + TLS、Shadowsocks。
- Hysteria2、TUIC。
- SOCKS5 链式代理和多 SOCKS5 负载均衡。

结果包含分享链接、订阅地址、二维码、端口、UUID 或密码、SNI、Reality 公钥和客户说明。

## 12. 管理后台

后台建议使用独立 `/admin` 入口，包含：

- 业务概览。
- CDK、批次和套餐管理。
- 核销、返还和人工审核。
- 部署任务和脱敏日志。
- 面板分类、上架、下架和紧急禁用。
- 适配器版本与更新。
- 购买链接、公告和客服信息。
- 资源推荐。
- 管理员、角色和权限。
- 登录记录和操作审计。
- 系统更新。
- 全站备份和上传恢复。
- 网站、安全、CDK 和安装设置。

角色至少包括超级管理员、运营管理员和售后管理员。支持修改管理员用户名和密码、2FA、恢复码、会话管理、禁用账号和强制退出其他设备。

## 13. 资源推荐区

后台可配置 VPS、域名、CDN、SSL、代理资源和其他配套服务。

资源字段包括名称、分类、Logo、简介、价格文案、地区、标签、推荐理由、HTTPS 跳转链接、排序、置顶、启用状态、展示时间和推广标识。

可展示在首页、CDK 页面、服务器连接页、配置不足提示页和安装结果页，并统计展示量和点击量。

## 14. 系统更新

后台显示当前版本、最新版本和更新日志，正式版固定使用稳定通道，并支持手动检查、手动更新和安全更新策略。

更新流程：

```text
获取版本信息
→ 下载更新包
→ 校验签名与 SHA256
→ 创建更新前备份
→ 解压到临时目录
→ 检查依赖
→ 数据库迁移
→ 切换版本
→ 重启服务
→ 健康检查
→ 完成后浏览器自动刷新
```

进度条必须来自真实更新阶段。更新失败时自动恢复旧版本和更新前数据。适配器支持独立更新和紧急禁用。

## 15. 全站备份与迁移

备份包括数据库、CDK 数据、部署任务、面板目录、适配器配置、购买链接、资源推荐、网站设置、管理员权限、上传资源和可选审计日志及 SSL 证书。

默认不包含 SSH 密码、SSH 私钥、过期敏感数据、依赖目录、可重新下载的构建产物和大量普通日志。

备份要求：

- 生成 `.pgbak` 文件。
- 支持密码加密。
- 包含版本信息和完整性校验。
- 支持手动、定时和更新前备份。
- 支持下载、保留数量和过期清理。

新服务器安装空白 PanelArk 后可选择“从备份恢复”，上传备份、输入密码、预览内容、检查版本、创建恢复前快照、恢复数据、执行迁移、重启并健康检查。

## 17. 技术架构

建议延续当前技术基础并重构：

```text
React + TypeScript + Vite
          ↓
Node.js + Express API
          ↓
持久化任务引擎
          ↓
部署 Worker
          ↓
SSH 执行器
          ↓
目标 Linux VPS
```

## 18. 安全基线

- 全站 HTTPS。
- SSH 主机指纹确认。
- SSH 密码和私钥默认不落盘。
- 短期敏感结果服务端加密。
- CDK 仅保存哈希。
- 日志自动脱敏。
- CDK 权益只能服务端验证。
- CSRF、防暴力登录、管理员 2FA 和 Session 管理。
- 安装源白名单、签名和校验和。
- 禁止任意命令和任意脚本 URL。
- 高风险操作二次确认和同服务器任务锁。
- 更新与恢复操作审计。
- 加密备份、恢复包校验和临时文件清理。

## 19. 需求变更与完成规则

- 本文档是当前确认的产品基线。
- 新需求先记录到本文档或进度台账，再进入实现。
- 未通过阶段验收的工作不能标记完成。
- 每完成一个阶段，必须同步更新 `PROGRESS.md`，记录完成内容、验证结果、遗留问题、重要决策和下一阶段入口。
- 如果阶段范围变化，必须记录变更原因，不能只覆盖原计划。
