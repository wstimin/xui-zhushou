# v2.6.2：修复 pa / sy 快捷入口缺失

## 证据与范围

现场确认 `/usr/local/bin/pa` 与 `sy` 缺失，`/opt/panelark/install.sh` 完整、语法通过且直接运行菜单正常，网站健康检查正常。无法仅据此确定是谁删除了入口。

源码确认两个恢复路径存在遗漏：在线更新执行器未修复缺失入口；安装脚本发现已安装或相同版本后直接返回，也没有修复入口。

## 修复

- 增加打包内置的统一快捷命令修复工具，安装、在线更新与独立服务启动复用同一实现。
- 重复执行安装命令只检查并修复入口，不下载构建包、不安装依赖、不重启网站。
- 在线更新通过健康检查后补建缺失入口。快捷入口冲突或权限错误记录到更新事件，不因此回滚已通过健康检查的网站。
- Linux 生产独立模式、root 运行的服务在启动时补检一次。这也覆盖旧版更新执行器安装新版后的首次启动，不要求旧执行器已具备新功能。
- Windows、非 root、开发环境、宝塔／1Panel／容器模式不执行宿主机启动自修复。
- 每个入口独立处理，`pa` 被其他程序占用也可修复缺失的 `sy`。不覆盖符号链接、目录、其他安装目录的入口或仅碰巧包含项目路径的脚本。
- 使用临时文件与原子发布设置 755 权限，参数完整传递；已正常的入口保持不变。

## 测试

`server/command-shortcuts.test.ts` 覆盖缺失修复、幂等、旧格式迁移、权限、同名命令、软链接、目录、不同安装目录、实际子进程启动修复、失败不阻断服务，以及带空格和引号的路径及子命令转发。

`server/update-shortcuts.test.ts` 在 Linux 使用真实更新执行器、临时 tar 包、目录切换与本地 HTTP 健康检查，核对更新完成后的入口实际执行、冲突保留、事件记录、内置依赖不重装与回滚目录清理。仅替换测试进程管理命令和快捷命令目标目录，不修改宿主机 `/usr/local/bin`。

安装脚本回归同时验证“已安装”和“相同版本”分支修复入口，并断言未调用系统依赖安装、构建包下载或 PM2。

本次发布不更新客户服务器。
