# 超级管理员全后台实操验收

## 验收方式

本轮按用户要求不使用 tabbit，不控制用户浏览器，也不修改生产服务器。

`server/admin-acceptance.test.tsx` 在 DOM 环境挂载真实管理页面，通过填写表单、点击提交/确认/取消等事件，调用监听在本机随机端口的真实 Express 服务。管理接口没有模拟，使用隔离 SQLite 文件与备份目录。操作后检查数据库字段、API 重新读取、导出内容和实际文件，并反复卸载/重新挂载页面验证持久化。

测试中仅外部发布站的下载受控，返回临时 Ed25519 密钥签名的清单及哈希匹配的文件，仍运行真实签名/哈希校验。受控任务执行器用于验证取消和售后，不冒充向真实 VPS 安装面板。

补充接口验收位于 `server/admin-management.test.ts`，包括初始与新增超级管理员的权限、CSRF、角色隔离、关联删除、失败回滚和历史备份恢复。所有用例纳入 `npm test`。

## 实际发现并修复的问题

1. 目录介绍不能真正清空：写入使用默认回退，读取也把空字符串当成未设置。修复两处并同时检查后台和公开目录。
2. 删除当前套餐后残留失效 ID：下拉框视觉上似乎已选其他套餐，但生成请求仍使用旧 ID。修复后以实际成功生成新码验证。
3. 恢复前快照及源备份从列表消失：恢复数据库覆盖本机备份登记。恢复时合并仍在磁盘上的本机登记，快照可继续下载/恢复/删除。
4. 恢复会话复活与页面停留旧管理态：清除备份中的所有会话、清 Cookie，并回到恢复后路径的登录页。
5. 历史运行任务复活：恢复的任务没有现场执行上下文，却保留运行状态和服务器锁。恢复后将历史活动任务标记中断，允许管理员继续售后管理。

## 明确不作虚假承诺

- 这是页面 DOM 交互与真实后端集成验收，不等同于真实浏览器视觉或原生下载对话框验收。
- 本轮不执行客户服务器上的升级重启、SSH 安装或破坏生产数据。系统更新执行器在 Linux 生产环境的真实切换，不能用隔离环境中的拒绝启动来冒充成功安装。
- 业务概览是统计，不提供伪造创建/修改；任务真实执行结果由执行器产生；审计历史不允许改写；目录新增安装项目需要真实适配器，而不是只创建一个名称。这些是业务语义，不是超级管理员权限缺失。
- 日常删除失败的在途保护仍保留：活动任务先安全停止；删除当前登录超级管理员、停用或降权自己会被阻止，避免锁死后台。管理员可通过另一超级管理员账号操作。
